## 2 · 定位与反定位

**定位**：主人在本机的**委托台** —— 他只做一件事（给出**最初的输入**），只收一样东西（**产物**）。工作台是这两个端点之间的界面，**中间一律不可见**。

> **设计宪法（主人 2026-09-27 定调 · 未来所有改动服从）**：
> ① 「我不在乎内部是怎么进行协作的，我只关心**最终的结果**」
> ② 「我负责的话，也只是**最初的输入**」
> ③ 「**结果是你能做到的任何事情**」（⇒ 不预设产物类型）
> ⇒ **入口 = 一个输入框（+ 可选附件）；出口 = 通用产物卡；内部一切不可见。**
> ⇒ **反证条款**：若某功能的作用是「让主人更了解内部」⇒ **违反宪法，不做**。

**反定位**（明确不做）：
- **不做内部可见面**：星图、节点拓扑、心跳、信箱、事件流脉冲、行为日志、节点生命周期、归属账本可视面 —— **全部不做**（依据 ①）
- **不做进度展示**：无进度条、无百分比、无阶段名 —— 唯一保留的中间态是「**在做**」一个点（主人在 2026-09-27 明确选择保留它作为最小确收）
- 不是 DSH 插件（不参与 profile 组合、不注入工具面）
- 不替主人决策、不冒充节点（发话一律 `from="owner"`）
- 不读 DSH 私有会话格式（`session.v3.jsonl.zstd`）—— 那会锁死未来（spec §4.5 修正 1）
- **不让主人当眼睛**：每版用 computer-use 自审后再交（9/15 诊断第 4 条，已是纪律）

**与旧定位的关系（一次反转，不是补充）**：v0.1–v0.4 的定位是「常驻桌面的**观察与控制台**」，服务对象是「想监控 agent 内部的人」。**这个用户不存在** —— 主人 9/15 的评价是「没有可用性」，2026-09-27 给出上述三条宪法时再次确认。v0.2 星图（= 看过程）→ v0.3 动作层 → v0.4 节点生命周期（= 起节点）**三步全踩在宪法要删的那半上**；§9 记有本日修订行与误读的病根。

## 3 · 术语

| 词 | 含义 |
|---|---|
| 委托（commission） | 主人的**最初输入**：一句话 + 可选附件。本产品的第一条轴 |
| 产物（artifact） | 我交付的**任何东西**：文件 / 图 / 视频 / 代码 / 网页 / 未知类型（降级为文件卡）。第二条轴 |
| 标记（mark） | 委托的全部状态，**只有三种**：`·` 在做 ｜ `✓` 已交付 ｜ `⚠` 需要你 |
| 请求（request） | `⚠ 需要你` 的正文：**做什么 + 为什么只有你能做**。它不是状态，是**一次打扰**（有门槛，见 I3） |
| 数据面（data plane） | `.workbench/` —— `commissions/` · `artifacts/` · `requests/` 三个目录。本产品只**写委托**，其余**只读** |
| 内部（internals） | 节点 / 心跳 / 信箱 / 拓扑 / 日志 / 行为流 —— **本产品一律不呈现**（宪法 ①） |

> **已废弃的术语**（v0.1–v0.4 的星图语言）：星 · 卫星 · 光弧 · 脉冲 · 归属账本 · 起步卡 —— 它们描述的界面依宪法 ① **已不做**。保留此行仅为读旧文档时的对照。

## 4 · 概念模型与不变量

```
主人 ──最初的输入（一句话 + 可选附件）──▶ 工作台 ──▶〔内部：一律不可见〕──▶ 产物卡 ──▶ 主人
```

**两端的形状**：
- **委托（输入）**：一句话 + 可选附件
- **产物（输出）**：**通用容器**，按类型选呈现（图 / 视频 / 代码 / 网页 / 文件 / 未知 ⇒ 降级为文件卡），能打开、下载、留档

**委托的全部状态只有三种**（此外没有第四种）：

| 标记 | 含义 | 是否打扰主人 |
|---|---|---|
| `·` | 在做 | 否 —— 一个点，**无进度条 / 无百分比 / 无阶段名** |
| `✓` | 已交付 | 否 —— 带产物数 |
| `⚠` | 需要你 | **是** —— 一条具体请求（做什么 + 为什么只有你能做） |

**不变量**：
- **I1 内部不可见**（宪法 ①）：界面不呈现任何节点 / 心跳 / 信箱 / 日志 / 拓扑元素。判据：源码级无相关 IPC 与视图 + 截图级无相关元素（双重，见 §7 C1）
- **I2 产物是一等公民**：产物不是消息附件 —— 它常驻、可回访、可再加工（这是本产品区别于 Telegram 的唯一理由）
- **I3 打扰有门槛**（宪法 ②）：`⚠ 需要你` 只在「非主人不可」时出现，且必含「做什么 + 为什么只有你能做」
- **I4 不预设产物类型**（宪法 ③）：任何我能做到的事都是合法产物 ⇒ 容器必须支持未知类型降级
- **I5 坏数据不致命**：任何单条损坏只跳过该条，不影响其余视图（§5.24：逃逸异常 = 宿主死因）
- **I6 零模型调用**：不发起任何 LLM 请求（无 key / endpoint / SDK）—— 它是界面，不是 agent
- **I7 写面最小**：应用只写**委托**；产物是只读引用（由爱丽丝交付时落盘）

## 5 · 契约（含调用点清单）

### 5.1 Tauri IPC 命令（前端 → Rust）

| 命令 | 入参 | 出参 | 调用点（前端） |
|---|---|---|---|
| `list_commissions` | — | `Commission[]`（含标记与产物数） | `src/App.tsx`（首帧 + 自适应轮询） |
| `submit_commission` | `text`, `attachments?` | 委托 id | 输入框组件提交 |
| `read_artifacts` | `commissionId` | `Artifact[]` | 产物面板（选中委托时） |

**已删除的命令**（v0.5 定位反转，依宪法 ①）：`bus_snapshot` · `dsh_status` · `dsh_recover` · `spawned_nodes` · `spawn_ref_node` · `stop_ref_node` —— 前者属「内部可见面」，后四者属「起停节点」，均不做。

### 5.2 后端事件（Rust → 前端）

| 事件 | 载荷 | 触发 |
|---|---|---|
| `commissions-changed` | `Commission[]` | 委托/产物目录内容指纹变化（**自适应轮询**：有焦点 150ms · 无焦点 700ms · 隐藏 2500ms，**隐藏优先于焦点**；窗口隐藏时不 emit，回前台自行补快照） |

### 5.3 数据面契约

工作台有自己的数据面 `.workbench/`（默认 `%USERPROFILE%\.workbench`，可用 `ALICE_WB_DIR` 覆盖）—— **不再读写 cluster 总线的 `nodes/` / `mailbox/` / `cluster-trace.jsonl`**。

| 路径 | 权限 | 说明 |
|---|---|---|
| `commissions/<id>.json` | 读 + **写** | 委托。**字段级分工**：工作台创建并写 `{v, id, text, attachments?, atMs}`；**爱丽丝只改 `status`**（`doing` → `delivered` / `needs-you`）。同一文件两个写者，各写各的字段，互不覆盖 |
| `artifacts/<commissionId>/` | 只读 | 产物目录：一件产物一个条目，`kind` 决定呈现（`image` / `video` / `code` / `page` / `file` / **未知 ⇒ 文件卡**）。**写者=爱丽丝**；工作台**不写、不改、不删** |
| `requests/<commissionId>.json` | 只读 | `⚠ 需要你` 的具体请求：`{v, commissionId, what, whyOnlyYou, atMs}`。**写者=爱丽丝** |

**容错**：坏的 / 缺字段的 / 超大的单条一律跳过，不影响其余视图（I5）；目录不存在 ⇒ 空视图（不是错误）。

### 5.4 跨端接口（两端的责任划分）

- **委托出发**：工作台写 `commissions/<id>.json`（`status=doing`）。**消费方在爱丽丝一侧**（读目录、认领、推进）—— 该消费机制**不属于本产品**；本产品只保证契约稳定，不实现、不假设其内部。
- **产物回来**：爱丽丝写 `artifacts/<commissionId>/`，并把 `status` 改为 `delivered`。
- **请求回来**：爱丽丝写 `requests/<commissionId>.json`，并把 `status` 改为 `needs-you`。
- **本产品不发起任何模型调用、不替主人转发、不判断任务该派给谁** —— 它只是两端的界面（I6）。

## 6 · 边界与信任

- **信任模型**：`.workbench/` 是**同机**数据面，**非安全边界** —— 同一用户账号下任何进程本来就能读写这些文件。应用不加认证（与旧总线的同一条理由）。
- **越权防范**：委托的 `attachments` 必须落在允许的根内，拒绝 `..` 与绝对路径穿越；产物目录由爱丽丝写入，工作台**只读**且不跟随符号链接。
- **隐私**：不落盘任何凭据；不硬编码本机路径（也避免公开仓库泄露本机路径）。
- **副作用**（v0.5 收敛）：**唯一外部可见副作用 = 写一条委托文件**。v0.3/v0.4 的「起进程 / 杀进程 / 删心跳 / 写归属账本」四项依宪法 ① 不做，随之消失的还有它们带来的旧账（Windows 上 `taskkill` 终止 Node **不触发 `SIGTERM`** ⇒ 进程不会自己清心跳 ⇒ 总线上攒出 13 个墓碑；见 §9）。
- **能力边界 ≠ 沙箱**：本产品不隔离任何东西，也不承诺隔离 —— 它只是两块界面的组合。
- **失败面**：读失败（目录不存在 / 坏 JSON / 超大）⇒ 跳过该条 + 空视图，**不伪造成功、不抛进主流程**（I5）；写失败（磁盘满 / 只读）⇒ 返回明确错误给界面，不静默。
