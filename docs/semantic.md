## 2 · 定位与反定位

**定位**：常驻桌面的**观察与控制台**。把「本机有哪些智能体节点、它们此刻在做什么、DSH 运行时是否活着」变成一眼可见，且**零模型调用**（不烧 token）。**v0.3 起它也是「动手的地方」**：稀疏态给起步卡（派任务 / 起一个参考节点）、节点详情给「停止并清理心跳」——但动作面**只到自己造的那点写面**（写 mailbox、起停自己起的参考节点），不替主人决策、不冒充节点。

**反定位**（明确不做）：
- 不是 DSH 插件（不参与 profile 组合、不注入工具面）
- 不是消息路由器（不替主人转发、不做批处理判断——那是主脑的活）
- 不读 DSH 私有会话格式（`session.v3.jsonl.zstd`）——那会锁死未来（spec §4.5 修正 1）
- 不做智能决策（只看与只转发，判断永远归主脑/主人）

## 3 · 术语

| 词 | 含义 |
|---|---|
| 总线（bus） | 文件系统契约，默认 `%USERPROFILE%\.dsh-cluster`，可用 `DSH_CLUSTER_DIR` 覆盖 |
| 节点（node） | 可被寻址的智能体运行时：身份 + 能力 + 信箱 + 行为落盘 + 结果回传。**harness 无关** |
| 心跳 | `nodes/<nodeId>.json`，节点每 ~10s 覆写；`atMs` 是判活时间戳 |
| 行为事件 | `cluster-trace.jsonl` 一行一阶段（`phase`），是 R6「行为必须落盘」的现成载体 |
| 快照（snapshot） | 应用一次性读取的总线视图；`fingerprint` 是内容摘要，用于判断"变了没" |
| 星（star） | 节点在星图里的呈现；**位置由 `hash(nodeId)` 决定**（确定性径向布局，见 `docs/DESIGN.md` §4） |
| 卫星（satellite） | 任务在星图里的呈现，绕其 `assignee` 星运行；无 `assignee` 则绕中央恒星 |
| 光弧（link） | 消息的呈现（`from → to`；`owner` 解析为中央恒星）；最近 8s 加亮一次 |
| 脉冲（pulse） | 行为事件的图形化刻度（`cluster-trace` 的 `phase` + `logs/actions` 的 `stage`），点开才是全文 |
| 归属账本（spawned ledger） | 总线根 `.workbench-spawned.json`（v0.4）：**只有工作台自己起的节点才登记在此**；它是「能不能停这个进程」的唯一凭据（防误停别人的进程） |
| 起步卡（starter） | 稀疏态（在线 ≤2 且无待办）时叠在星图上的引导层（v0.3）：现状一句话 + 派任务 + 起一个参考节点 + 看全貌 |
| 活跃度（active / visible） | **可见 + 有焦点**才算「在用」（v0.3/perf）：驱动轮询节流（150/700/2500ms）与 `body.idle` 装饰动画暂停 |

## 4 · 概念模型与不变量

```
Rust 后端（唯一写者=mailbox）
  bus::snapshot(dir)  ──读──▶  nodes/ · mailbox/ · state/ · cluster-trace.jsonl
        │
        └─ 指纹变化 ──▶ emit("bus-changed", Snapshot) ──▶ React 前端渲染
```

**不变量**：
- **I1 写面收口（2026-09-22 修正：v0.4 起写面不止一处）**：应用只写两类文件——`mailbox/<to>/<id>.json`（代表主人发消息）与总线根 `.workbench-spawned.json`（**归属账本**，只记录它自己起过的节点）；不改总线其它任何文件。
- **I2 只读判活**：节点在线判据 = `now - atMs < 30_000`，与插件 `DEFAULT_OFFLINE_AFTER_MS` 同源；应用**不猜测**节点状态。
- **I3 零模型调用**：应用不发起任何 LLM 请求（无 key、无 endpoint、无 SDK）。
- **I4 坏数据不致命**：任何单文件损坏（坏 JSON / 缺字段 / 超大）只跳过该文件，不影响其余视图（§5.24：逃逸异常 = 宿主死因）。
- **I5 harness 无关**：只依赖总线标准产物；`displayName`/`harness`/`capabilities` 等为**可选字段**，缺失时回退显示，不报错。
- **I6 归属边界（v0.4，本文件是唯一会起进程的地方，故必须最保守）**：起进程**只起我们自己的脚本**（`E:/alice/self-plugins/dsh-agent-cluster/scripts/ref-node.mjs`，可被 `ALICE_WB_REF_NODE` 覆盖；**不接受任何调用方传入的可执行路径**）；停进程**只停账本登记过的节点**（不在册的 `nodeId` 一律拒绝——绝不停主人的 DSH 主脑或别人的进程）；`nodeId` 由工作台生成（`<主机名>-wb-<序号>`）；起成功后**等心跳真的出现**才算成功（「不落盘 = 不算节点」）。
- **I7 空转不烧机（2026-09-15 常驻开销优化）**：轮询节奏随「可见 / 有焦点」自适应——有焦点 150ms · 无焦点 700ms · 最小化/隐藏 2500ms（**隐藏优先于焦点**）；窗口被压住时不 emit 事件。判据：`poll_cadence_ms` 三档**严格递减**（Rust 单测），且实测常驻开销 546 → 148（无焦点）→ **85 秒/小时**（最小化）。

## 5 · 契约（含调用点清单）

### 5.1 Tauri IPC 命令（前端 → Rust）

| 命令 | 入参 | 出参 | 调用点（前端） |
|---|---|---|---|
| `bus_snapshot` | — | `Snapshot` | `src/App.tsx` 首帧 |
| `send_message` | `to`, `text`, `kind?` | 消息 id | `src/views/NodePanel.tsx` 提交 |
| `dsh_status` | — | `DshStatus` | `src/App.tsx`（10s 轮询） |
| `dsh_recover` | — | 启动说明 | `src/App.tsx` 顶栏按钮 |
| `spawned_nodes` | — | `SpawnedNode[]`（归属账本视图） | `src/views/NodePanel.tsx`（**自己问**「这个节点是不是我起的」；不靠上层透传） |
| `spawn_ref_node` | `displayName?` | `SpawnedNode`（**返回时心跳已确认出现**） | `src/views/Starter.tsx` 起步卡「起一个参考节点」 |
| `stop_ref_node` | `nodeId` | 结果文案 | `src/views/NodePanel.tsx`（**二次确认**后才调；只有账本在册的节点才显示该入口） |

### 5.2 后端事件（Rust → 前端）

| 事件 | 载荷 | 触发 |
|---|---|---|
| `bus-changed` | `Snapshot` | 内容指纹变化（**自适应轮询**：指纹先行短路——未变即跳过全量快照；节奏 150 / 700 / 2500ms 见 I7）。**窗口隐藏时不 emit**（省掉渲染器唤醒重绘；前端回前台自己补快照，故不会看到陈旧界面） |

### 5.3 总线读写契约

| 路径 | 权限 | 说明 |
|---|---|---|
| `nodes/*.json` | 只读 | 心跳；字段 `nodeId/atMs/pid/role/profile/workspace/port/...` |
| `mailbox/<node>/*.json` | 读 + **写** | 收件箱；写时 `v=1`、`from="owner"`、`ttlMs=86400000` |
| `mailbox/<node>/done/*.json` | 只读 | 已投递归档 |
| `.workbench-spawned.json` | 读 + **写** | **归属账本**（v0.4，总线根）：`[{nodeId,displayName,pid,atMs,workdir}]`；写者=工作台，读者=它自己（`spawned_nodes`）；坏 JSON 读成空表（总线是外部世界，形状不可假设） |
| `tasks/<taskId>.json` | 只读 | 任务台账（`scan_tasks`；协议主副本见 `dsh-agent-cluster/docs/semantic.md` §5.5） |
| `logs/actions/*.jsonl` | 只读 | 行为事件（`scan_actions`；上限 24 文件 / 每文件 400 行 / 共 600 条，`detail.taskId` 回填给同组每行） |
| `state/*.json` | 只读 | 幂等集合 / 重试账（当前仅计入指纹） |
| `cluster-trace.jsonl` | 只读 | 行为事件流；取尾部 300 条 |

### 5.4 `from` 字段语义

工作台**代表主人**发话 ⇒ `from = "owner"`。它不冒充任何智能体节点（冒充会污染"谁说的"因果链）。

## 6 · 边界与信任

- **信任模型**：总线是**同机**协作面，非安全边界（对照 spec R1/R2）。应用不加认证，因为同一用户账号下任何进程本来就能读写这些文件。
- **越权防范**：`send_message` 校验目标名不含路径分隔符与通配符，防止写出 `mailbox/` 之外的路径。
- **隐私**：不落盘任何凭据；workspace 路径从心跳读取，**不硬编码**（也避免公开仓库泄露本机路径）。
- **副作用（2026-09-22 修正：原文写「唯一外部可见副作用 = 写一条消息文件」，v0.3/v0.4 起已不止一条）**：① 写消息文件（代表主人发话，`from=owner`）② **起进程**（`spawn_ref_node` 只起参考适配器脚本；`dsh_recover` 会调 `.dsh/init-dsh.ps1`——该脚本第一步是清理既有 DSH 进程，故有二次确认）③ **杀进程 + 删心跳**（`stop_ref_node`，仅限账本在册节点，同样二次确认）④ 写归属账本。**代价如实记**：`stop` 必须由启动方收尸——Windows 上 `taskkill` 终止 Node **不触发 `SIGTERM`**，进程不会自己清心跳（总线上原有的 13 个墓碑全是「起而不停」攒下的）。
